# Collection Studio

Collection Studio помогает создавать коллекции карточек для мобильных игр. Задайте тему, получите от 1 до 5 наборов по десять карточек, выберите удачные версии и экспортируйте результат.

В программе есть русский и английский интерфейсы, светлая и тёмная темы. Язык выбирается по настройкам устройства; для остальных языков используется английский. Выбранное оформление сохраняется между запусками.

## Требования к запуску и проверенная среда

Для запуска готового приложения:

- **Система:** Mac с macOS 13 Ventura или новее.
- **Процессор:** Intel или Apple Silicon; универсальный архив содержит обе архитектуры.
- **Первый запуск:** сборка использует локальную подпись ad-hoc без нотарификации Apple. macOS может запросить [подтверждение в настройках безопасности](#если-macos-блокирует-первый-запуск).
- **Комплект:** Electron и подготовленная библиотека референсов входят в приложение. Node.js и npm нужны для [сборки из исходников](#building-from-source).

Для генерации изображений дополнительно нужны:

- установленный [Codex CLI](#connect-codex) и выполненный вход через ChatGPT;
- доступ учётной записи к выбранной модели и инструменту генерации изображений;
- доступные лимиты Codex и подключение к интернету.

Встроенную библиотеку можно просматривать сразу после открытия приложения.

Где и что проверялось:

- **Локально:** macOS Sequoia 15.7.7, Apple Silicon (arm64). Пройдены проверка типов TypeScript, ESLint, автоматические тесты и сборка приложения.
- **Codex CLI:** адаптер проверен с версией `0.167.0-alpha.4.1`.
- **В GitHub Actions:** автоматические тесты и сборка кода на Linux; тесты, упаковка и публикация универсального приложения на macOS ARM64.
- **В опубликованной версии 0.1.2:** скачанный ZIP проверен по SHA-256; после распаковки проверены подпись, версия приложения, ресурсы и наличие исполняемого файла для Intel и Apple Silicon.

## Сборка из исходников

Для сборки подготовьте:

- Mac с macOS 13 Ventura или новее;
- Node.js 22.13–22.x либо Node.js 24 и новее;
- npm.

В корне репозитория выполните:

```sh
npm ci
npm run build
npm start
```

В `resources/` уже находятся изображения референсов и подготовленная база знаний. Они входят в клон репозитория и ZIP с исходниками GitHub.

Полезные команды:

- `npm run dev` — запуск разработки с перезагрузкой при изменениях.
- `node node_modules/electron/install.js` — установка исполняемого файла Electron, если установочные скрипты зависимостей были отключены.

### Подключение Codex

1. Установите [Codex CLI](https://developers.openai.com/codex/cli/). Готовый нативный вариант работает самостоятельно.
2. В Терминале выполните `codex login` и выберите **Sign in with ChatGPT**.
3. В приложении откройте **Настройки**.
4. Выберите модель генерации: **GPT-6.1 Terra** по умолчанию или **GPT-6.1 Sol**. В поле **Модель планирования коллекции** можно задать отдельную модель для плана.
5. Сохраните настройки и нажмите **Проверить подключение**.

Если автоматический поиск CLI завершился без результата, укажите полный путь в поле **Путь к Codex CLI**, сохраните настройки и повторите проверку. При запуске из Finder приложение также проверяет стандартные пути Homebrew и `~/.local/bin`.

Проверка подключения подтверждает запуск CLI и вход через ChatGPT. Она завершается за 15 секунд или показывает инструкцию для устранения проблемы. Доступ к выбранной модели, инструменту изображений и лимитам определяется при запросе к Codex.

Сведения о работе с провайдером:

- Адаптер проверен с CLI `0.167.0-alpha.4.1`. Для другой версии предусмотрена [калибровка](#maintenance-and-live-calibration).
- Планирование, визуальный анализ и генерация изображений расходуют лимиты Codex.
- Приложение использует сохранённый вход CLI через ChatGPT.
- Пожелание к качеству изображения передаётся текстом запроса.

## Работа с наборами

1. Откройте **Новый набор**, задайте тему и пожелания к изображениям. Выберите от 1 до 5 вариантов; по умолчанию создаётся один.
2. При необходимости включите **Добавлять золотые карточки**. Они займут часть десяти позиций набора.
3. Нажмите кнопку создания. Программа подготовит план и начнёт рисовать карточки.
4. Откройте карточку, чтобы посмотреть изображение, использованные референсы и историю версий. Выберите подходящую версию, перегенерируйте её или заблокируйте выбор.
5. Для нескольких вариантов нажмите **Выбрать для сдачи** у предпочтительного набора.
6. Нажмите **Экспорт набора**, чтобы сохранить текущий готовый вариант. Из предпросмотра игровых окон также можно отдельно скачать PNG.

Дополнительные возможности:

- Кнопка **AI** составляет краткие пожелания на английском по теме набора. Это обращение к модели.
- Каждый набор содержит ровно десять сюжетов и все четыре обычные категории композиции. Золотые карточки относятся к категории 5.
- При создании нескольких вариантов программа проверяет уникальность сюжетов между ними.
- **Одобрить и добавить в библиотеку** сохраняет выбранное изображение как дополнительный пользовательский референс.

### Пауза и продолжение

1. Нажмите **Приостановить**. Программа прекратит назначать новые задачи; уже начатые запросы могут завершиться.
2. Дождитесь остановки проекта перед изменением выбранных версий или удалением.
3. Нажмите **Продолжить**, чтобы вернуться к работе с сохранёнными изображениями.

Изображения создаются двумя обработчиками одновременно. После перезапуска прерванные проекты остаются на паузе. Для незавершённых запросов сохраняется отметка о неизвестном результате; дальнейшую работу запускает пользователь.

### Ручная доработка и теги позиций

Откройте панель карточки, выберите версию и способ работы:

- **Новая попытка:** нажмите **Перегенерировать** с пустым полем указаний.
- **Доработка выбранной версии:** заполните **Указания для доработки** и запустите перегенерацию. Программа возьмёт за основу сохранённое изображение.

Теги позиции задают требования к карточке. Их можно редактировать в остановленном проекте при разблокированной карточке.

- Сначала сохраните теги, затем запустите перегенерацию.
- Удаление тега снимает соответствующее требование.
- Запреты указывайте в поле доработки.
- Ограничения категории и персонажей остаются фиксированными.
- История хранит предыдущие изображения, проверки, теги и использованные референсы.

### Проверки, исправления и лимиты запросов

В настройках есть два независимых ограничения. Оба **по умолчанию равны 0**.

| Настройка                                           | При значении 0                                           | При положительном значении                                                                                  |
| --------------------------------------------------- | -------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| Максимум перегенераций одной карточки               | Проверка и автоматические исправления карточки отключены | Модель проверяет сюжет, силуэт, персонажей, категорию и фон; программа допускает заданное число исправлений |
| Максимум раундов перегенерации после общей проверки | Проверка и исправления всего набора отключены            | Модель проверяет связи между карточками сетки 5×2; после каждого раунда исправлений сетка проверяется снова |

Как применяются эти настройки:

- Лимит карточки действует на каждую цепочку первоначальной или ручной генерации.
- Для лимита набора в N раундов выполняется одна первоначальная проверка и до N повторных проверок после исправлений.
- Каждый новый проект сохраняет свои настройки проверок.
- Автоматические исправления сохраняют предыдущие версии и точное изображение, на основе которого сделана доработка.
- Блокировки карточек и общий лимит запросов изображений действуют на протяжении работы.
- Неопределённые наблюдения сохраняются в **Технической диагностике**. Сдача по текущему протоколу доступна после подготовки десяти изображений и остановки проекта.

При техническом сбое запрос изображения повторяется с теми же указаниями и референсами. Повторы продолжаются до сохранения изображения, паузы пользователя или исчерпания лимита. Каждая такая попытка учитывается в расходе запросов и диагностике.

Чтобы изменить лимит изображений:

1. Остановите проект.
2. Откройте **Техническая диагностика → Журнал работы и лимиты**.
3. Укажите нужное число запросов, максимум — 150.

Счётчик учитывает запросы изображений, включая технические повторы и доработки. Планирование и проверки учитываются отдельно.

Исторические проекты сохраняют свои настройки и проверки. Явное продолжение или перегенерация архивного проекта может перевести его на текущий протокол; переход записывается в историю. Подробности — в [описании процесса проверки композиции](docs/COMPOSITION_ONLY_WORKFLOW.md).

## База знаний и генерация

В группе **База знаний** находятся четыре раздела:

- **Карточки** — исходные и пользовательские референсы, фильтры, описания и анализ отдельных объектов.
- **Наборы** — состав исходных наборов, наблюдения о композиции и сводная статистика.
- **Категории** — примеры композиций и правила каждой категории.
- **Стиль** — общие правила отрисовки и указания для генерации.

В разделах «Карточки», «Наборы» и «Категории» можно добавлять и удалять объекты. Изменения базы применяются к следующим проектам. Исходные изображения и история созданных наборов сохраняются.

Новый проект использует подготовленный анализ библиотеки. Если часть данных изменилась или отсутствует, программа показывает состояние подготовки в настройках.

Порядок создания набора:

1. Программа распределяет категории, узоры и цвета по сетке 5×2.
2. Подбирает и фиксирует исходные референсы для каждой позиции.
3. Отправляет модели один запрос на разработку набора и проверяет структуру ответа. При структурной ошибке допускается ограниченное число повторов.
4. Создаёт десять изображений через общий пул обработчиков.
5. Выполняет проверки композиции и исправления, если они включены в настройках.
6. Сохраняет версии для выбора и экспорта.

Основные правила подбора:

- Планирование опирается на общую статистику библиотеки.
- В новом плане каждая пара «цветовое семейство — узор» уникальна; соседние по горизонтали и вертикали позиции имеют разные цветовые семейства.
- Для каждой позиции выбирается от двух до восьми подходящих исходных карточек.
- Примеры категорий и изображения для доработки получают свои роли в запросе.
- Большие подборки объединяются в листы референсов с сохранением размера изображений, соответствий и хешей. Так подборка укладывается в ограничение адаптера: пять путей к изображениям.
- Шаблоны сдачи используются для оформления результата в игровых окнах.

## Экспорт

Для текущего протокола `composition-v1` подготовьте десять выбранных изображений и остановите проект. При экспорте программа проверит целостность файлов.

ZIP с набором содержит:

- `cards/01.png` … `10.png` — карточки 430×480 в формате PNG и цветовом пространстве sRGB;
- `masters/01.png` … `10.png` — сохранённые PNG полного разрешения в sRGB;
- `history/<card-id>/<attempt-id>.png` — предпросмотры сохранённых версий;
- `contact-sheet.png` — выбранную сетку;
- `delivery/` — изображения игровых окон и список выбранных версий;
- `selection.json`, `run.json`, `style-profile.json` и `report.md` — данные набора и отчёт;
- `journal.md` и `diagnostics.json` — журнал работы и диагностические данные с удалёнными секретами.

У исторических проектов также может быть `quality-warnings.json`. Метаданные сохраняют бриф, запросы, использованные исходники, модели, попытки и выбранные версии. Изображения игровых окон включают графику шаблонов и подписи.

Для остановленных проектов доступны:

- **Скачать журнал работы** — хронологический журнал на русском.
- **Техническая диагностика → Скачать данные для диагностики** — JSON с данными проекта, профиля и журнала.

Сохранённые запросы и ответы остаются на исходном языке. Пробелы в исторических данных отмечаются в отчёте.

## Ресурсы и локальные данные

В `resources/` хранятся готовые материалы для сборки: 200 уникальных PNG и данные базы знаний.

| Расположение                                        | Содержимое                                                                                |
| --------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `resources/references/`                             | 160 исходных карточек, проверенных по хешам                                               |
| `resources/knowledge/images/`                       | 16 окон наборов, 5 примеров категорий, 4 шаблона сдачи и 15 листов наборов без оформления |
| `resources/knowledge/catalog.json`                  | Семь исходных документов, сведения о контекстных изображениях и составе листов            |
| `resources/knowledge/visual-catalog.json`           | Визуальный анализ карточек, категорий и 16 наборов                                        |
| Остальные `resources/*.json` и `resources/prompts/` | Профиль, правила, настройки планирования, макеты, классификации и шаблоны запросов        |

Дополнительные выгрузки и исследования хранятся в игнорируемом каталоге `local-sources/`. Изображения в нём ссылаются на основные файлы через символические ссылки. См. [организацию локальных исходников](docs/LOCAL_SOURCES.md). Для предоставленной графики действуют исходные условия использования и распространения.

Данные программы распределены так:

- Каталог пользовательских данных Electron хранит настройки, правила, рабочую базу знаний, импортированные референсы и историю проектов.
- Его подкаталог `runs/` по умолчанию содержит проекты.
- `COLLECTION_STUDIO_DATA=/absolute/path/to/runs` задаёт другое место для проектов и материалов их выполнения. Настройки и база знаний сохраняются в каталоге пользовательских данных.
- В каждом проекте находятся `run.json`, снимок профиля, версии изображений, контактные листы и `execution.jsonl`.
- Запросы Codex для проекта записываются в его `_jobs/`. Для других операций используются `_codex-jobs/`, `_catalog-jobs/` и `_knowledge-jobs/` в корне каталога проектов.

Для резервного копирования:

1. Закройте приложение.
2. Сохраните весь каталог пользовательских данных Electron.
3. Сохраните отдельно заданный каталог проектов, если используете `COLLECTION_STUDIO_DATA`.

Подтверждённое удаление остановленного проекта перемещает его папку в системную Корзину. Общая библиотека и отдельно экспортированные файлы остаются на своих местах.

## Разработка и проверка

Приложение написано на Electron, React и TypeScript. Для проверки изменений выполните:

```sh
npm run typecheck
npm run lint
npm test
npm run build
```

Тесты работают с заранее подготовленными изображениями и ответами провайдера. Они проверяют:

- правила планирования и подбор референсов;
- наличие ресурсов и целостность изображений;
- лимиты, исправления, паузу, продолжение и прерывания;
- чтение исторических проектов;
- локализацию и экспорт.

### Локальная сборка для macOS

```sh
npm run package:mac
```

На Apple Silicon команда создаёт:

- `release/mac-arm64/Collection Studio.app` — универсальное приложение;
- `release/Collection-Studio-mac-universal.zip` — архив для скачивания;
- `release/SHA256SUMS.txt` — контрольную сумму архива.

Перед заменой текущей сборки программа проверяет локальную подпись и ZIP. Порядок публикации описан в [инструкции по распространению](docs/DISTRIBUTION.md).

### Обслуживание и калибровка с обращением к модели

Для обновления ресурсов и проверки провайдера предусмотрены команды:

- `REFERENCE_ART_DIR=/absolute/path/to/originals npm run prepare:library` восстанавливает PNG всех карточек каталога по SHA-256. Для импорта полного экспорта панели используется `SOURCE_EXPORT_DIR=/absolute/path/to/export npm run prepare:library`.
- `SOURCE_EXPORT_DIR=/absolute/path/to/export npm run prepare:knowledge` импортирует документы и контекстные изображения, затем обновляет листы наборов без оформления. В экспорте должны быть `Файлы.json` и `Разделы.json`.
- `npm run prepare:references` восстанавливает восемь опорных референсов из локального экспорта или заданных оригиналов и манифеста.
- `npm run kb:sync` обновляет и публикует визуальный анализ. Отдельные этапы — `npm run kb:analyze-cards` и `npm run kb:analyze-sets`. Эти команды обращаются к Codex и расходуют лимиты подписки. Промежуточные результаты находятся в `output/catalog/cache/`. См. [обслуживание базы знаний](docs/KNOWLEDGE_CATALOG.md).
- `npm run calibrate:codex` создаёт одно изображение через GPT-6.1 Sol и выполняет визуальную проверку по исторической схеме. Результат сохраняется в `output/codex-calibration/`; запросы расходуют лимиты подписки.

После подготовки ресурсов проверьте изменения каталогов и изображений перед публикацией.

## Архитектура и дополнительные материалы

Код разделён на четыре части:

- **Предметная область** хранит правила и проверки.
- **Слой приложения** выполняет сценарии работы через узкие интерфейсы.
- **Инфраструктура** подключает Codex, файловую систему, изображения и экспорт.
- **Интерфейс** показывает состояние и передаёт действия через ViewModel и проверяемые сообщения Electron IPC.

Тексты запросов и настраиваемые правила хранятся в JSON. Ответы модели проверяются перед использованием.

Каждый запрос `codex exec` выполняется в отдельном рабочем каталоге с песочницей `workspace-write`. Приложение отключает коннекторы, плагины, инструменты командной оболочки и делегирование агентам. Переменные окружения `OPENAI_*` и `CODEX_API_KEY` отфильтровываются; входом через ChatGPT управляет CLI.
