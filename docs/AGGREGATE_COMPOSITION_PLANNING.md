# Aggregate composition planning

## Source model

The prepared visual catalogue supplies complete ten-card source sets and their classified members. Every complete source set has equal weight. Ordinary mode excludes gold members and normalizes each remaining source to ten cards; an all-gold source contributes no ordinary observations. Mixed mode includes narrative observations. The catalogue currently contains sixteen source sets.

The deterministic planner fits integer category counts and joint category/support/backdrop/pattern/depth/context/actor distributions. It approximates the corpus statistics rather than treating every marginal mean as a separate quota. Every ordinary category is present; category 5 is included only when requested. Generated joint patterns must have at least two distinct, approved, high-confidence original reference images. Unsupported observations remain in the statistics but cannot supply unsupported generation slots.

`CollectionCorpusStatistics.positionStatistics()` counts all eleven controlled composition axes separately at each original row-major slot, splitting ordinary-only, mixed, gold-only and ordinary-member cohorts. The current sixteen sources contain six ordinary sets, nine mixed sets and one gold-only set. All nine mixed sets put category 5 in a consecutive suffix; gold frequencies for positions 1–10 are 0/0/0/0/0/0/1/3/7/9. An offline 20,000-permutation audit found no convincing ordinary-card positional dependence for category, pattern, backdrop, support, camera, background color, depth, context density or placement, including tests that retain category positions. These observed frequencies must not become fixed ordinary-slot quotas.

For new slot-first plans, `SourcePositionPlanner` applies the gold-suffix rule only when at least three mixed source sets unanimously support it. The current evidence (nine of nine, with source IDs) is frozen in optional `composition.positionPolicy`. `SetRhythmPlanner` preserves this suffix while satisfying color/pattern and neighbor constraints; it cannot move gold cards into ordinary slots. Category counts, exact-match reference eligibility and all per-card facets remain unchanged. The design request receives the policy and its authored guidance from `resources/position-planning.json`. New source contradictions disable inference for new plans. Historical contracts without the optional policy keep their original ordering.

## Current execution order

1. Allocate ten slots before requesting subjects. Freeze each category, required visual facets and selected original reference IDs. `referenceIds` records the matching candidate pool; `selectedReferenceIds` records the exact selected inputs. New runs shuffle the full exact-match pool separately for each variant and occurrence of a joint pattern, seeded by the persisted run ID and variant index, then take up to eight originals. Pools of eight or fewer retain every image in shuffled order. Required facets, source statistics, representative-derived preferences and grid color/pattern relationships remain deterministic. Persist the selected order before model design and reuse it across planning repairs, pause/resume and card regeneration. Historical frozen selections are never reshuffled. Never pad the budget with unrelated rendering examples.
2. One structured design-model request receives all slots, their selected images and the producer brief. It returns a connected concept, ten distinct subjects, common lighting/material/palette direction and per-slot descriptions. New requests for more than one set snapshot `subjectUniqueness=batch-unique-v1` in the run profile. Their response additionally requires a normalized `subjectType` per card, shared by synonyms and color/material/genre variants of the same object. The model plans all sets together and must avoid repeated object types across the entire request. No independent model plan review or second descriptive call is made in this protocol.
3. Validate JSON structure, identities, declared compatibility, gold mode and source bindings in code. This checks model-declared metadata, not semantic truth. Contradictory subjects are returned for bounded automatic correction. Slot patterns and reference selections remain unchanged. If the final structurally valid design still declares incompatible subjects, automatic mode records explicit warnings and proceeds with the original slot contract.

   For `batch-unique-v1`, code checks normalized names and declared types together across all requested sets before any image calls. Collisions record both set/slot locations. The bounded correction request includes the rejected full design and asks to replace later conflicting subjects while retaining valid subjects, stories and frozen slots. Missing types or unresolved collisions remain structural failures even in best-effort mode; they cannot fall back to image generation. Types survive compilation, saved drafts, plans, pause/resume and export. Single-set requests retain their existing ten-subject checks and do not require types. Model-declared types can still miss semantic duplicates if the model assigns different keys; no independent semantic-verification guarantee is claimed.

4. Build each image prompt from canonical rules, the shared art contract, that slot's requirements and its frozen original images. Reuse stored visual classifications. Do not analyze unchanged originals again. All ten cards use the same worker queue, with default concurrency two and no special first-card stage.
5. Visually review each generated card against the requested subject, original slot facets and the same originals. Code compares the observed facets with the requirements. Failed checks trigger bounded revisions using the previous candidate as an edit base; originals retain style authority. A weaker revision does not replace a stronger previous version.
6. Assemble the ten selected cards into a neutral sheet. Select multiple clean source sheets deterministically for comparison, without adopting one source layout. Perform a separate whole-set visual review and bounded targeted corrections.
7. Save images, exact input manifests, review evidence and execution logs. Deliver complete sets with explicit quality warnings when artistic repair limits are exhausted. Technical failures, missing files, invalid image bytes, explicit pause and request budgets remain enforced.

For one successful set without corrections, the application makes one design request, ten image requests, ten card reviews and one set review. Revisions add requests only when needed. Optional art-direction assistance and library maintenance are separate user workflows.

## Historical compatibility

Archived profiles, original prompt snapshots and legacy fields remain readable. They are evidence, not active first-card gates. Previously generated images and archived logs are not rewritten. New runs use `workflowVersion=planned-set-v2` and `planValidation=deterministic-slots-first-v1`.

Historical profiles without `subjectUniqueness` retain their previous subject policy, including saved slot designs without `subjectType`. Resuming or regenerating them does not silently enable cross-set uniqueness. New multi-set runs persist the policy before planning; pause/resume reuses it and rechecks the complete saved plan before generation.

## Verification

`npm test`, typecheck and lint exercise orchestration, pause/resume, bounded repairs, exact-version reviews, reference identity and exports using offline providers. `npx tsx scripts/audit-slot-inputs.ts` checks both ordinary and mixed modes against the bundled private catalogue and real source image hashes, with model execution explicitly forbidden. Its synthetic subjects do not establish artistic quality. Outputs are saved under ignored `output/slot-input-audit/`.
