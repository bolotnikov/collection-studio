# Разнообразие раскладок и участников сцен

Для новых наборов приложение выбирает раскладку по случайному ключу запуска и номеру варианта. Ключ влияет на цвета и порядок обычных карточек при сохранении числа категорий, совместимых композиций и исходных референсов. Золотые карточки занимают последние позиции.

При подборе раскладки действуют ограничения:

- Все четыре обычные категории присутствуют в наборе.
- Цвет и узор каждой карточки имеют подтверждение в исходном каталоге.
- Соседи по горизонтали и вертикали имеют разные цветовые семьи.
- Пара «цветовая семья / узор» встречается один раз.
- Число цветов и частота их повторения остаются в допустимых пределах.
- Последовательность цветовых семей отличается от сохранённых наборов и других вариантов текущего запроса. Синий и голубой считаются одной семьёй.

Поиск учитывает баланс категорий, фонов и частоту цветов. Вес случайной составляющей задан в `resources/set-rhythm.json`, поле `variationWeight`. Если поиск не находит допустимой новой раскладки, запуск останавливается до заказа изображений. История для сравнения берётся из сохранённых запусков; удалённые запуски в ней отсутствуют.

Новые планы используют `entityUniqueness=depicted-entities-v1`. Для каждой карточки модель перечисляет в `depictedEntities` главные предметы, самостоятельный реквизит и всех действующих персонажей. У каждой записи есть тип, нормализованный идентификатор и описание внешности. Детали конструкции, надетая одежда и общие фоновые плоскости описываются в задании карточки.

Перед генерацией приложение проверяет:

- Наличие главного предмета в перечне обычной карточки.
- Соответствие числа людей заданному золотому слоту.
- Отсутствие повторных идентификаторов людей и предметов во всём запросе.
- Отсутствие одинаковых описаний внешности под разными именами людей.

Один герой в одиночной и парной сцене считается повтором. Главный предмет обычной карточки также нельзя повторить как самостоятельный реквизит золотой сценки. При конфликте модель получает отклонённый план и позиции повторов. Число исправлений ограничено настройками планирования; неустранённый повтор блокирует заказ изображений.

Генератор получает внешность участников текущей карточки и перечень участников остальных карточек, которых следует исключить. Включённая общая визуальная проверка сравнивает людей и реквизит на готовой сетке. Проверки метаданных устанавливают соответствие объявленного плана; внешнее сходство разных описаний требует проверки изображений. При нулевом лимите общей проверки она пропускается.

Ключ запуска, история раскладок, выбранные слоты и участники сохраняются вместе с профилем и планом. Пауза, продолжение и экспорт используют сохранённые данные. Исторические профили без нового протокола читаются по прежним правилам; готовые изображения сохраняются.

Локальные проверки: `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`. Тесты используют локальные заглушки и не заказывают изображения.
