# Image prompting contract

Reviewed against [OpenAI's image prompting guide](https://developers.openai.com/api/docs/guides/image-prompting) on 2026-11-13. This implements applicable prompting guidance for ordinary collectible object cards and optional category-5 character scenes; it is not a guarantee of artistic quality or a model migration.

## Canonical rules and data flow

`resources/production-requirements.json`, section `image-prompting`, is the canonical Russian production policy for prompt construction, visible under Style. Rendering rules and composition categories come from the source art and Miro text in `resources/canonical-style-rules.json`; OpenAI guidance does not define the game's art style. Prompt templates remain in `resources/prompts/production.json`. Requirements and templates are snapshotted with each new run profile; later edits do not change an active or resumed run.

| Concern                        | Authored/planned contract                                          | Generation and verification                                                                                                                                                                                                   |
| ------------------------------ | ------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Deliverable, scene and subject | Brief, card subject/description/role                               | Labeled card prompt, producer wishes and output constraints                                                                                                                                                                   |
| Materials, shape and texture   | `visual.materials`, `visual.silhouette`, shared material treatment | Art director inspects originals; card review receives planned visual requirements                                                                                                                                             |
| Composition                    | `visual.composition` and assigned category                         | Explicit viewpoint, orientation, scale, placement, margins and background; independent category check                                                                                                                         |
| Style, color and light         | Shared rendering/lighting contract and `visual.paletteRole`        | Concrete art direction under original reference authority; card and set review                                                                                                                                                |
| References                     | Selected original evidence with hashes and take/ignore directions  | `GenerationRequestBuilder` numbers the exact image array; category diagrams and supplemental art have distinct purposes                                                                                                       |
| Revision                       | Actionable correction and selected attempt                         | Previous immutable master is appended as the last input and identified by attempt ID; preservation is subordinate to the accepted contract                                                                                    |
| Exclusions                     | Content rules and accepted art contract                            | No text, logos, watermarks, interface frames or unrelated objects; categories 1–4 exclude people and characters; enabled category 5 permits one or two characters, including people; complete silhouette and thumbnail checks |

`PromptBuilder.sourceContext` includes active requirements even without a knowledge corpus. Planning resolves concrete choices into existing typed fields; independent plan review rejects vague or contradictory art direction. The visual selector also receives the operative requirements. It builds on the accepted plan instead of replacing its style.

`CardProductionService` wraps both prepared and fallback prompts through `GenerationRequestBuilder` before calling either provider. The request records producer wishes, numbered art/source inputs and revision context in the persisted attempt prompt. Codex transport packing retains these original input numbers in its position mapping. The OpenAI adapter preserves the same array order. Review receives original references and category evidence, excluding the previous generated candidate so it cannot become style authority.

The additive `generation.context.v1` template opts a saved catalog into numbered requests and revision-base inputs. Historical catalogs without that key remain valid and keep their previous generation behavior; the new template is never silently inserted into them. Existing template placeholder contracts are unchanged.

## Applicable scope and controls

The canonical `environment-background` requirements define calm recognizable settings with explicitly enumerated secondary objects. The [160-card source audit](ENVIRONMENT_BACKGROUNDS.md) supplies hash-bound observations and numbered input evidence without changing source categories. New composition reviews distinguish concrete unplanned background objects from permissible local texture; only corroborated mandatory defects under the additive review protocol can spend the existing correction budget. Source detail observations are not artistic scores or universal source quotas. Historical snapshots without the policy/template retain their behavior.

- Categories 1–4 contain ordinary objects without people or characters. When gold mode is enabled, category 5 permits one or two characters, including people; describe and verify pose, gaze and interaction against the approved scene. Exact typography recommendations do not apply because all categories forbid text. Photorealistic prompting would contradict the original stylized rendering. Source references remain authoritative.
- New runs normalize recognized legacy blanket exclusions to explicit category scope, then record the active gold-mode requirements. Existing custom rule text is preserved. The art-direction suggestion receives the same mode. Saved rendering defaults are migrated with a hash-addressed backup; historical run profiles remain unchanged.
- Request one image and the smallest coherent correction. A review may identify related defects; do not force a one-word edit that leaves the approved brief unsatisfied. Pixel-identical preservation is not promised.
- Generation uses only the ChatGPT-authenticated Codex CLI. Native Codex generation owns its quality controls; new Codex prompts omit the former quality-intent instruction. Archived briefs and prompt snapshots retain their original values and behavior. The producer UI does not present requested quality as a measured result. Preserve request budgets.
- Codex requests portrait art; delivery is a centered 430×480 crop of the immutable master. When card verification is enabled, it inspects silhouette completeness. Historical square API outputs remain unchanged, but the API adapter is no longer available. Output positioning remains probabilistic.
- Keep deterministic plan validation, frozen slot reference identity, bounded repair, current-version review evidence and whole-set checks. Prompt compliance cannot prove visual compliance.

## Offline verification

`tests/GenerationContext.test.ts` checks requirement propagation through all stages without a corpus, planned visual details in review, exact numbered input order, revision-base behavior, historical catalogs, and both provider adapters. The API transport is intercepted locally and the Codex worker is mocked; neither generates art or uses real credentials. Its production-service cases verify that a revision receives its selected immutable master and reviewers retain only original evidence. Existing workflow tests exercise card/plan failures, interruption, resume and export gates.

Run `npm run typecheck`, `npm run lint`, `npm test`, and `npm run build`. These establish contract and transport behavior. A separate authorized generation and human visual comparison are required to assess artistic results.
